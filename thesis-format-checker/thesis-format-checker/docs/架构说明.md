# 架构说明

## 一、分层

```text
cli.py ──▶ engine/pipeline.py ──▶ detectors/*.py     （读模板基准、读文档对象）
                │                        ▲
                │                        │ 取证
                └──▶ checks/cXX_*.py ────┘          （每条规则一个方法）
                          ▲
                          │ 元数据
                     checks/catalog.py               （165 条规则清单）
```

| 层 | 目录 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 规则层 | `checks/` | 大类 → 类，规则 → 方法；对外给出每条规则的结论 | 不直接操作 Word |
| 取证层 | `detectors/` | 读取模板基准与文档对象，产出 `Finding` | 不决定调用顺序 |
| 基础层 | `core/` | Word 会话、docx 上下文、有效格式、范围识别、批注写入、排版快照、结果缓存 | 不含任何规则判断 |
| 调度层 | `engine/` | 决定顺序、异常降级、结果汇总、报告输出 | 不含规则算法 |

## 三、一次检测的执行流程

1. `engine.pipeline.extract_baseline(template_ctx)`：按 `catalog.PROVIDERS` 顺序
   读取模板基准，写入 `structure`、`headers`、`equations` 等命名空间；任一组
   读取失败只会把自己标记为受限。
2. `engine.pipeline.check_sections(baseline, document_ctx, mapping)`：按同样顺序
   调用各取证的检查函数，得到有序问题列表（顺序即批注顺序）。
3. `detectors/word_effective/runner.py`：对需要 Word 解析有效格式的规则
   （页边距、字体、字号、缩进、行距、页眉文字、标点）执行旧版流程。
4. `engine.pipeline.run_comparison`：适配旧版结论、合并、去重，把每条结论写成
   Word 原生批注；`save_comments_only` 逐件复制原包，只替换批注相关部件，
   落盘前校验正文除批注外没有任何改动。
5. `engine.reporting`：输出命令行摘要，可选导出 JSON 报告。

### 性能：静态先筛 + Word 精查 + 结果缓存

一次完整检测里最贵的是 Microsoft Word（COM）阶段。调度层现在按“先便宜、后昂贵”
的顺序决定要不要调 Word（对应性能优化第 3、5 条）：

```text
docx 静态取证（秒级）
      │
      ├── 结论已确定 ────────────────▶ 直接用，不碰 Word
      ├── 只需分页事实（032/165.1）──▶ 复用 Word 流程顺手取到的 render_facts
      └── 需要坐标（078/087/033/098/059）
                │  静态先筛：这些小类真的出现“无法判定”吗？
                │  需要哪些段落？只需坐标还是也要图片/表格？
                └──▶ core/word_layout.read_layout（只读筛出来的段落）
```

* **静态先筛**（`detectors/rendered.layout_requirements`）返回“需要的段落号 +
  是否需要图片/表格坐标”；筛不出需求就完全不读排版；
* **结果缓存**（`core/cache.py`）把 Word 流程结论与排版快照存到磁盘，缓存键 =
  缓存结构版本 + **源码指纹** + 输入文件**内容指纹** + 影响结论的参数。任何源码或
  输入变化都会自动失效，无需手工清理；命令行 `--no-cache` / `--cache-dir` 可控。
  命中缓存的第二次检测不再打开 Word，通常能压到 1 分钟以内。

### Word 阶段的提速（Tier 0）

Word 阶段曾经约占整次检测的 85%，瓶颈不是算法，而是**同一份文档被从头到尾走了四遍、
每遍都逐段访问 COM**（样例论文约 2 万次调用）。现在：

| 优化 | 做法 | 位置 |
| --- | --- | --- |
| 一遍建表 | 文本/样式名/大纲级别/是否在表格**读一次缓存**，正文段、标题、空段、目录四处消费共用 | `core/word_facts.WordFacts` |
| 分页按页读 | 页边界每页一次 `GoTo`；段落页码/节号**第一次被问到才读**；空白页按页范围判定（跨页长段落不再误判） | `core/word_pages.PageFacts` |
| 会话合并 | 排版几何（题注/表格/图片/公式/目录页码）在**同一次 Word 会话**里顺手读出，不再为几何第二次打开 Word | `core/word_layout.read_layout_in_session` + `detectors/rendered.content_layout_request` |
| 不再写废批注 | 最终输出由调度层写批注，Word 流程里那份会被丢弃的副本批注与整篇保存直接跳过 | `compare_word_documents(write_comments=False)` |
| 关闭后台任务 | 读格式阶段关闭屏幕刷新、拼写/语法检查与后台重排（`Options.Pagination`），读页码前恢复并 `Repaginate()` | `core/word_session.tune_for_detection` |

**精度如何保证**：所有属性仍然走与逐段读取**完全相同的 COM 接口**（`Range.Text`、
`Style.NameLocal`、`OutlineLevel`、`Information(3)/(12)`…），只是不再重复读。
`tools/verify_word_facts.py --production` 会把事实表读到的文本、起始位置、样式、
大纲级别、是否在表格、页码、节号、节页范围、空白页与**逐段参考实现**逐项对照，
要求 0 处不一致才验收；该工具同时记录了两种读法的 COM 调用次数。

> 说明：曾评估过用 `Document.Content.Text` 一次取回全文再切分（1 次调用代替约 1000 次），
> 但对照实测显示表格的单元格标记与行结束标记会让切分结果与 `Range.Text` 错位
> （每行差 1 个字符、后续段落位置累计漂移），因此**不作为**正式实现。

### docx 阶段的提速（Tier 1）

Word 阶段减半后瓶颈转到 docx 静态检测，按 cProfile 热点逐项处理（都不改变判定逻辑）：

| 优化 | 做法 | 位置 |
| --- | --- | --- |
| 同一份文档只算一次 | 标题记录（原 40 次/运行）、题注（10 次）、目录快照、域扫描（6 次）、公式记录、格式对象进上下文缓存 | `core/docx_context.memo` |
| `qn()` 缓存 | 热路径统一换成 `lru_cache` 版本，消除数千万次前缀解析 | `core/xmlutil.qn` |
| 可见文字一次遍历 | 原逐节点回溯祖先链 → 一次深度优先遍历 | `core/xmlutil.visible_text` |
| 样式解析缓存 | 按 `(style_id, type)` 缓存；缓存挂在 `DocumentPart`（`document.styles` 每次访问都是新代理） | `core/docx_context.install_style_cache` |
| 批注锚点只解析一次 | 同一结论只在第一次问锚点时全篇查找 | `engine/pipeline._paragraph_anchor` |
| 模板剖面缓存 | 同一份模板换论文时复用模板侧有效格式基准 | `runner._load_template_profile` |
| 并行预热 | Word 阶段（等 COM）并行完成 docx 侧全篇扫描，只写缓存、不产生结论 | `engine/pipeline._prewarm_docx_scans` |
| 几何复用事实表 | 排版几何不再重读全篇文字与位置，直接用段落事实表缓存 | `core/word_layout._paragraph_records` |

实测（67 页 / 1044 段样例）：整次检测 875 秒 → **418 秒**；docx 静态检测 44 秒 → **17.5 秒**
（并行预热后只占 8.4 秒）；批注锚定与写入 64 秒 → **1.4 秒**；命中缓存的第二次检测 **61 秒**。

## 四、模板比对原则：同一层级 + 同一位置

论文格式检测是**模板比对**，不是“先在模板里找出一个全文唯一的标准，再套到论文上”。
判定口径统一为（实现见 `core/pairing.py`）：

1. **同一层级**——按段落样式名、标题级别、题注种类、用途角色把两份文档各自分组；
2. **同一位置**——组内数量**相同**时逐个对应（论文第 3 个正文段对模板第 3 个正文段）；
3. **同一层级兜底**——数量不同时取该层级最常见的样例。模板通常只放几段样张，
   按比例硬对齐会把封面“声明”段错配到模板“摘要说明”段，因此不做比例映射；
4. 只有模板**完全没有该层级的样例**时，才输出“无法判定”。

因此模板里同时存在多份样张（例如正文字号 12 磅 75% + 10.5 磅 22%）时，
不再对全篇输出“无法判定”，而是逐段和各自对应的模板段比较。

使用位置：

* `detectors/paragraphs.py`——071/076/077（段落属性）、073（标题/题注缩进）、070（同用途文字）；
* `detectors/word_effective/profile.py` + `runner.py`——045–047（标题）、067–069（字体字号）、
  072（首行缩进）、074/075（行距段间距），模板剖面保留 `body_samples` / `heading_samples` 逐段基准。

## 五、扩展与维护

### 改一条规则

在 `checks/cXX_*.py` 里找到 `check_<编号>`。若逻辑仍由 `detectors/` 提供，
方法体是 `return self.evidence("<编号>")`；要换成独立实现，直接把算法写进方法
（用 `self.fail` / `self.unknown` 产出结论），再从 `catalog.PROVIDERS` 对应条目
的 `rules` 中移除该编号即可，调度与报告无需改动。

### 新增一条规则

1. `catalog.RULE_TITLES` 登记编号与标题（编号连续，每类 11 条）；
2. 对应大类里补 `check_<编号>`；
3. 若由现有取证提供，把编号加入对应 `PROVIDERS[*].rules`。

### 新增大类

1. `catalog.CATEGORIES` 追加元数据（key/index/名称/模块名/类名/说明）；
2. 新建 `checks/cXX_*.py`（继承 `CategoryChecker`）与 `detectors/xxx.py`；
3. `checks/registry.py` 的 `CATEGORY_CHECKERS` 登记；
4. `catalog.PROVIDERS` 增加该大类的取证条目（顺序即批注顺序）。

### 为什么保留 `detectors/` 而不是把算法全部写进类里

把算法整体搬进类方法需要同时解决跨大类的共用读取逻辑（页眉、目录、题注、公式
互相引用），在没有回归测试保护的情况下风险很高。当前分层保证：

* 每条规则的**入口**唯一（`check_<编号>`），改规则只需看一个方法；
* 每条规则的**状态与来源**可查（`catalog.py` + `thesis-checker rules`）；
* 每类共用的读取逻辑只有一份，不会出现两套实现互相不一致。

迁移是按条进行的：改一条、跑一次测试，逐步把 `detectors/` 的算法收进类方法。

## 六、等级、批注格式与实现状态

### 等级

| 等级 | 含义 | 处理要求 |
| --- | --- | --- |
| 错误 | 违反学校模板的硬性要求（缺组成部分、页边距、字体字号、行距、标题格式、目录结构、页码、编号连续性等） | 必须修改 |
| 警告 | 影响规范性或与模板不一致（页眉下边框、目录引导线、题注格式、脚注格式、附录编号等） | 建议修改 |
| 提醒 | 排版细节与风格偏好（全半角混用、中英文边界空格、多余空行、日期书写形式等） | 可改可不改 |

等级写在 `checks/rule_specs.py` 的每条细粒度规则上；修复一处规则时只改那一行。

### 批注格式

批注正文只有一处渲染实现（`core.models.build_comment`），模板固定为：

```
【等级】这条规则在讲什么
应该：模板要求 / 期望值
实际：当前文档的真实值
```

示例：

```
【错误】封面题目格式不符合模板
应该：字号 19 磅、加粗
实际：字号 16 磅、未加粗
```

* `无法判定`、不适用及未实现只进入报告，所有批注写入入口统一拒绝未知结论及含
  “无法判定”的文案，不再维护按规则族过滤的例外清单。
* 普通批注不带定位前缀；段落、节、页序与锚点位置均保留在 JSON 中。
  无法可靠定位时只报告，不写到文首。

避免对单元格内图片再输出一次“无法判定”。

### 标题层级树（先看编号与目录，再退回样式）

现实论文经常把正文段落误用「标题 2」样式（样例论文有 255 段），只按样式/大纲级别
识别会把整段正文当标题，进而产生大量误判。`detectors/headings.py` 因此按三层证据
重建标题树（`_build_heading_levels`，按文档缓存）：

1. **目录域缓存**（`toc 1/2/3`）——文档自己声明的层级，优先级最高；
2. **正文编号**——`第X章` / `N` / `N.N` / `N.N.N`；文档出现 `第X章` 时，`N` 记为 2 级、
   `N.N` 记为 3 级（与南农模板/论文的编号约定一致）；
3. **样式与大纲级别**——兜底，且必须通过“像标题”检查（≤40 字、无句末标点）。

其它约束：表格单元格里的编号不算标题；封面题目（`Title` 样式）不算章节标题；
单独的 `N 标题` 需要样式佐证，`1.1` 这类多级编号还要求父级已出现过；
大纲级别不可读时保留原有“无法判定”提示。

**前置区不参与标题判断**：摘要页之前（封面、题名页、原创性声明/授权声明页）只由
封面模块按模板同位置比对，不进入标题层级树。声明页标题常写成“××大学本科毕业论文
（设计）原创性声明”并套用「标题 1」样式，旧口径会把它当一级标题，进而对整页报
045/049/050/070/073 等格式错误。裁剪边界由 `core/scope.front_matter_end` 统一给出
（第一条“摘要/目录”标志，且要求其之前确实出现过封面/声明类内容），docx 侧
`_build_heading_levels` 与 Word 侧 `collect_headings` 共用同一口径。
“封面要素”按学校名、毕业设计/毕业论文、题目、姓名、学号、学院、专业、指导教师、
职称、密级、分类号等取证——封面页通常**并不出现“封面”二字**。

**编号序列按“章”分组**：论文每章的子级编号通常从 1 重新开始（第二章又是 1.1、1.2…），
所以 `check_heading_numbering_errors` 的序列状态键是「用途 + 层级 + **章标识** + 本级编号
路径」，而不是只按层级。同时把“记账”和“判定”分开：一条标题拿不到模板唯一基准
（或编号读不出来）时仍然登记它的实际编号，只有下一次拿到基准才比较——否则中间
一条标题会留下状态空洞，把下一条同父标题的编号误报成“应为 1”的跳号。

样例论文实测：标题从 395 段降到 149 段，与论文自带目录 **89/89 条层级一致、0 冲突**。

Word 侧（`detectors/word_effective/headings.py`）共用同一套判据：排除目录域缓存与封面题目、
要求“短且无句末标点”、`N` 级编号需样式佐证。修好后论文标题在两条路径上分别识别为
**149 段（docx）与 147 段（Word）**，此前 Word 侧是 395 段（含 255 段误用标题样式的正文）。

### 正文范围：前置/后置分区

**需要排版才能判定的规则用 Word 分页事实**：`core/word_pages.read_page_facts`
在 Word 流程里读一次分页事实（总页数、每段所在页、每节页范围），交给
`detectors/word_effective/pagination.py`：

* **054 标题与后续内容同页**：标题落在页末、正文从下一页开始 → 确定问题；
* **030 章节另起页**：模板的一级标题设为“段前分页”时，论文每章必须另起页；
* **040 页码**：自动页码域由 Word 计算，同页不会重复/跳号；只有“手工数字冒充页码”
  （页脚写着 1 但没有 PAGE 域）才报错，各页会显示同一个数字。

管道顺序：先跑 Word 流程拿到分页事实，再把事实挂到 docx 上下文
（`context.render_facts`），最后跑 docx 取证——这样 030/040 等规则在排版可用时给出
确定结论，读不到时保持原“无法判定”，不会把结论说死。

**前置部分逐变体比对（022）**：普通页/首页/偶数页三个变体分别与模板对应变体比较
“有没有内容、是文字还是动态页码域、文字是否一致”。含 PAGE 域的变体只比结构，不猜
域值；摘要/目录与正文挤在同一节时也照样逐变体给出确定结论，不再打包成“无法判定”。
**页脚按区域级比对**：前置部分用罗马页码是正常做法（模板自己也这样），因此页脚只比
“有没有页码域、是固定文字还是自动页码”，不会因为模板把页码写在偶数页变体、论文写在
普通页变体就报“不应出现页脚”。

**封面字段的有效格式（013/015/018/020）**：

* **字符单位缩进换算**：`w:ind/@w:firstLineChars`、`@w:leftChars`、`@w:hangingChars`
  按“1 字符 = 当前字号”换算成磅值（`core.docx_context.effective_paragraph`），
  不再因为“字符单位”把封面字段判成“无法完整确认”；
* **字体回退**：模板封面字段的值常是空白（只有“题 目:”标签），按值取字体必然为空；
  这时回退到整段文字（标签与填写值同字体），个别 run 读不到字体时用整段主导值补齐；
* **空格排版**：封面题目/字段靠空格排版时，对齐方式不具可比性，改比“前导空白个数”；
* **多行题目**：题目折行形成的后续段落按字段值处理，不再单独当成一个字段。

**声明页（020）**：原创性声明与使用授权声明一起检查——作者签名/作者日期、
授权页的作者签名、**导师签名、导师日期**各自成条；值区间里出现图片（手写签名扫描件）
视为已签名；同一行里“作者签名 + 导师签名”时，图片只算它旁边那一个标签。

**页眉页脚批注的锚点**：本机 Word 16.0 实测拒绝页眉页脚内批注，但支持正文
零长度范围批注。`word_layout` 读取真实页边界（含跨页长段落），页眉问题落在
本页正文顶部边界，页脚问题落在底部边界。`point_comments.add_boundary_comment`
只插入批注标记，不圈选标题、校徽或正文，不增加空格、段落或图形。
复杂对象边界、同页跨节或无法唯一匹配时只进报告，不跳过该对象另找无关段落，
也不从底部回退到顶部。短页底部指现有正文末端，无法无损地创建纸张下边距锚点。
显式分页符独占上一页的片段不视为正文末端，取上一页最后正文段落的段末；
禁止在段首分页符前插入引用 run，因为 Word 会因此改变下一页段前距。
含 `m:oMathPara` 的显示公式段落仅报告：本机 Word 原生 `Comments.Add` 同样会
把这类公式改按行内方式排版。检测结论不删除，报告明确记录未写批注原因。

**页面归属与共享配置**：取证阶段保存 `page_story`、`page_variant`、`page_scope`，
不从文案推断，不把缺失变体当普通页。Word 实际 `HeaderFooter.Index` 判定首页/
普通页/偶数页；奇偶页开关按打印页码及首页设置筛选受影响页面。该开关来自
文档级 `evenAndOddHeaders`，相同差异跨节只写一次；报告保留每节结论及全部受影响页。
普通页眉页脚问题按节及变体筛选，在每个受影响页分别写入，同页相同缺失内容跨规则合并；
029 的不同页眉变体独立取证，关闭的首页页眉不作为可见差异，继承内容继续核对后续节。
JSON `page_comments` 记录实际页序、
段内偏移、Word 位置、零长度范围和受影响页序，便于重新打开 Word 验证。

**组成部分顺序的定位**：规则 010.1 在模板缺少明确顺序或存在冲突时没有论文
违规锚点，因此不附默认首段；确定的顺序倒置仍锚在倒置的组成部分标题。
这项修复独立于封面图片识别，不靠排除校徽掩盖错误定位。

**目录条目结构（065）**：在 Word 排版流程里判定——条目与页码是否被分页拆开
（条目跨页）、条目占几行（错误换行）、某页是否只剩一条（孤立条目）、以及空白条目；
没有排版事实时只保留一条限制说明。

**缺失组成部分的批注位置（009）**：缺少附录/致谢这类结论没有具体段落，
`detectors/outline.py` 与 `detectors/structure.py` 按“它应处的位置”取锚点——
优先落在它后面第一个已有组成部分（附录 → 致谢），其次落在前面最后一个已有部分，
最后落在文末，绝不把这类批注挂在封面第 1 段。

**节对应关系自动推导**：论文与模板的分节数常不同（样例模板 11 节、论文 5 节，
封面+声明、摘要+目录可能被合并），因此不再要求使用者手写 `section_map`：
`detectors/pages.auto_section_map` 按节内文字推断节角色（封面、声明、摘要、目录、正文），
为每个论文节选择“角色一致，否则角色重叠最多且唯一”的模板节，`engine.pipeline` 在
开始检测前把这个自动映射注入两侧（docx 取证与 Word 有效格式流程），显式配置优先。
模板同角色节之间基准不一致、仍无法唯一对应时，这类“请配置 section_map”的提示
按“模板未涉及”处理——只进报告、不写批注。

Word 侧原先按样式名采集正文，会把封面、声明、摘要等前置内容也当成“正文样例”，
导致正文基准取到封面字段的字号（10.5 磅）并对整篇论文报“正文字号不符”。
现在 `core/scope.collect_body_paragraphs` 与 docx 侧同口径：从第一个正文标题开始、
遇到参考文献/致谢/附录停止，封面与声明不再进入正文统计；文档没有标题结构时才退回原逻辑。
另外，`collect_body_paragraphs` 与 docx 侧 `_body_records` 都会按 `front_matter_end`
再裁一次前置区（显式 `start_text`/`start_paragraph` 映射除外，配置怎么写就怎么用），
这样即使某个封面段落被误用「标题 2」样式，也不会成为正文格式基准。

Word 侧的正文范围还排除两类“看着像正文、其实不是”的段落：**图表题注**
（`图2-2 模型整体流程图`、`Tab.3-1 …`）与**编号标题**（`第X章`/`第X节`、`N.N…`，
以及“第X章”体系下的 `N 标题`）。样例论文里题注用五号字、标题用三号字，
混进正文样本后会按正文基准报“正文字号应为小四/英文数字字体应为 Times New Roman”，
实测这三类误报从 89 条降到 4 条。

### 模板未涉及的规则：直接跳过

模板里没有对应对象/样例时（例如南农模板没有密级、分类号），规则对这份论文并不适用：
`core.docx_context.unknown()` 会识别“模板没有/缺少/未提供…”这类措辞并改为
`Status.NOT_APPLICABLE`，`engine.pipeline` 对其**不写批注、不计入“无法判定”**，
只在报告里作为“已跳过”统计。模板本身的完备性由 `tools/check_template.py` 负责提示。

### 批注锚点、文案与去重

**锚点只在核对得上时才写**：批注必须落在真正出问题的文字上。段号命中的段落、
按摘录文字命中的段落（Word 段号与 docx 段号存在偏移时取与记录段号最接近的一处）
都能核对；两者都对不上时**不猜位置**，该结论只进 JSON 报告（`report_only`），
不会再被挪到文首（封面）上。旧版 Word 流程的结论如有段号无摘录，会在写盘前
补上段落文字摘录，供调度层按文字核对。

**批注文案不带“位置：第 N 段”**：批注本身已经贴在问题文字上，重复写段号没有
信息量；定位信息仍保留在结构化结果的 `location` 字段里（JSON 报告与人工核对用）。
只有显式开启汇总（`--merge-repeats N`）时，汇总批注才保留位置行——否则看不出它
覆盖哪些段落。

**批注面向普通用户**：抬头只写等级与问题标题（不写规则编号），正文用中文描述
“应该/实际”——不出现 `True/False`、`U+0020`、`alignment`、`line_spacing_rule`
或 `('', False)` 这类内部取值；公式没有可读文字时用“公式（编号 3-1）”代替，
空白值写“无”。有确切 start/end 或唯一摘录时无损拆分 run，只圈出对应字符，
无法安全匹配的复杂范围只报告，不扩展到整段。声明填写项使用所属声明名称及独立字段范围。
不再整段大面积覆盖。

`engine.pipeline` 在写批注前做两步收敛，**报告与批注使用同一份结论列表**：

1. **同一段落重复去重**（`dedupe_findings`）：按“规则编号 + 状态 + 锚点段落 +
   应该/实际 + 文字范围”去重，而不是按文案措辞——旧版 Word 流程与新取证模块
   对同一问题措辞不同，只按文案去重会漏掉；定位不到段落时改用更细字段，避免误合并。
2. **同类问题跨段落合并**（`merge_repeated_problems`）：同一规则、同一“应该/实际”
   在 ≥3 个段落重复时合成一条汇总批注，位置写成“第 156、157… 段（共 54 处同类问题）”，
   明细段落号保留在 JSON 的 `merged_locations` 里。阈值可用 `--merge-repeats N` 调整，
   `0` 表示不合并。

   **默认不合并**（`--merge-repeats 0`）：每个出问题的位置各写一条批注，不做跨段落
   汇总；需要“一条汇总 + 位置列表”的写法时再显式传 `--merge-repeats N`。

CLI 摘要会打印“去重：同一段落重复合并 N 条；同类问题跨段落合并 M 条”。

两条补充口径（2026-10 实测后加入）：

* **整段属性类规则不带文字范围去重**：字号/字体规则会把一段文字按脚本切成多个
  片段，同一段上的同一问题只保留一条批注（字符级/标点级规则 124–132 仍按位置区分）。
  合并位置列表也会去重，避免“第 517、517 段”这样的重复位置。
* **文字锚点必须核对**：Word 段落号可能因文本框与 docx 段落号偏移。
  只接受原段号与摘录相符的段落，或可核对的摘录匹配；不按就近段落或文末兜底。
  页眉页脚走独立的真实页边界路径，定位失败时不得重新进入普通批注写入器。

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_checks_architecture.py   # 架构自检
.\.venv\Scripts\python.exe -m pytest -m "not integration"               # 全部单元测试
```

与模板比对口径直接相关的测试（都不需要打开 Word）：

* `tests/test_word_correspondence.py`——同层级分组、同位置配对、越界与兜底；
* `tests/test_word_profile_samples.py`——模板剖面的逐段/逐标题基准；
* `tests/test_detectors_paragraphs.py`——模板有多种样例时按同位置判定。
* `tests/test_cache.py`——结果缓存往返（含整数段落号键、排版 dataclass 还原）、
  缓存命中后不再调用 Word 流程、静态先筛的取舍；
* `tests/test_word_facts.py`——段落事实表/分页事实与逐段读取**逐值一致**，
  且重复消费不再产生新的 COM 访问；
* `tools/verify_word_facts.py --production 真实论文.docx`——在真实 Word 上做
  同样的逐项对照（文本/位置/样式/页码/节号/节页范围/空白页，要求 0 处不一致）；
* `tests/test_effective_format_spans.py`——Word COM 段落与 python-docx 段落都能读
  span 格式，混合格式按二分收敛而不是逐字符；
* `tests/test_rendered_layout.py` / `tests/test_page_comments.py`——排版几何规则与
  按页批注锚点。

高校交付模板前，用 `tools/check_template.py` 做体检（写法要求见
[模板编辑规范.md](模板编辑规范.md)）；`tests/test_template_check_tool.py` 覆盖该工具。

`tests/test_checks_architecture.py` 会用 `ast` 解析各取证模块源码，核对
`catalog.PROVIDERS` 登记的编号与模块内部声明的编号完全一致，防止目录与实现脱节。
